# Граф денег · HackAlem AI / Freedom

Локальный анализ направленной сети переводов: проверка данных → граф и сообщества →
гипотезы ролей → очередь проверки → три CSV и согласованный снимок для API.
Роли и оценки — объяснимые гипотезы, не вероятность преступления.

В `codex/scoring-rules` подключён без изменений графовый модуль коллеги из
`codex/data-graph` (`3651a714`). Реализованы пакетный запуск и `--serve` для
опубликованного API C (`codex/api-ui`, `a749d9c`). Файлы C остаются в его ветке;
до интеграции тимлидом подключаются через отдельный checkout, как показано ниже.

## Установка

Python **3.12**, Linux/macOS; команды выполняются из корня репозитория.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install .
```

Windows PowerShell: создание окружения — `py -3.12 -m venv .venv`, активация —
`.\.venv\Scripts\Activate.ps1`. Остальные команды с `python` одинаковые.
Версии расчётных библиотек зафиксированы в `pyproject.toml`. После обновления
ветки повтори `python -m pip install .`, чтобы обновить установленный пакет.

## Один запуск

Положи выданные `nodes.parquet`, `edges.parquet`, `transactions.parquet` в `data/`.
Файлы можно хранить в другой папке и передать её через `--data`.

```bash
python -m moneygraph run --data ./data --out ./out
```

Период по умолчанию — **2026-07-01…2026-07-31**, глубина — четыре колена,
порог исходной выборки — 5 000 KZT. Другой период задаётся явно:

```bash
python -m moneygraph run --data ./data --out ./out --period-start 2026-07-01 --period-end 2026-07-31
```

Команда печатает `run_id`, папку результатов и время полного запуска.
В `out/runs/<run_id>/` находятся:

| Файл | Что содержит |
|---|---|
| `nodes_roles.csv` | Все клиенты, роль, уверенность, кластер, приоритет, evidence ≤200 символов |
| `clusters.csv` | Размер, seed, точный внутренний оборот, ведущие gid, гипотеза назначения |
| `top_nodes.csv` | Первые 30 клиентов; при равенстве приоритета сортировка по gid |
| `features.parquet` | Полная таблица признаков из графового модуля |
| `transactions.parquet` | Все нормализованные операции с `tx_ref`, включая повторные строки |
| `explanations.jsonl` | Правила, кандидаты ролей, ограничения, вклады в приоритет |
| `graph.json` | Направленные связи и узлы с признаками и результатами scoring |
| `quality.json` | Проверки качества и ограничения выгрузки |
| `manifest.json` | Входные хеши, конфигурация, код, версии библиотек, счётчики и хеши результатов |

`out/current.json` указывает на последний полностью записанный запуск. API должен
открывать один снимок целиком через `open_current`, а затем сохранять его `run_id`.
Контракт и пример чтения: [docs/pipeline.md](docs/pipeline.md).
Исходные данные, результаты расчёта и секреты не включаются в коммиты.

## Общий запуск с API/UI

В объединённом командном checkout с `moneygraph/api` и `frontend/dist`:

```bash
python -m pip install '.[serve]'
python -m moneygraph run --data ./data --out ./out --serve
```

Открыть http://127.0.0.1:8000. При занятом порте добавить `--port 8001`.
CLI проверяет хеши завершённого снимка и передаёт его каталог в `create_app` C.
Транзакции находятся внутри снимка: API не требует отдельного --data.

До объединения веток можно проверить связку из нашей ветки без merge и без
редактирования C. Вторая папка создаётся один раз:

```bash
git fetch origin
git worktree add --detach ../moneygraph-api origin/codex/api-ui
python -m pip install '.[serve]'
PYTHONPATH=.:../moneygraph-api python -m moneygraph run --data ./data --out ./out --serve
```

PowerShell: вместо префикса PYTHONPATH выполнить
`$env:PYTHONPATH = ".;../moneygraph-api"`, затем обычную команду с `--serve`.
Для этой проверки использована версия C `a749d9c`. Сборка frontend уже включена
в его ветку; Node не нужен. При другом расположении сборки доступен `--static-dir`.
Сам по себе `pip install '.[serve]'` устанавливает библиотеки, а не чужую ветку.

## Проверки

```bash
python -m pip install '.[dev]'
python -m pytest -q
```

Проверка с выданными данными (Linux/macOS):

```bash
MONEYGRAPH_DATA_DIR=./data python -m pytest -q
```

PowerShell: сначала `$env:MONEYGRAPH_DATA_DIR = "./data"`, затем `python -m pytest -q`.
Без переменной проверки реального набора пропускаются; синтетические выполняются.
Запуск включает исходные тесты коллеги, scoring и проверки публикации снимков.

На предоставленном наборе: **2 248 узлов, 3 119 рёбер, 4 840 операций,
105 кластеров, 30 строк top**. Полный CLI в среде разработки занял 2–3 секунды
включая экспорт и публикацию; установка и API не входят. Это замер контейнера
Linux x86_64 с Python 3.12.14, а не гарантия времени на любом ноутбуке.
Проверена установка wheel с зависимостями в отдельное виртуальное окружение;
`pip check` успешен. Совместный прогон A+B+C: **112 тестов**, включая реальный
Uvicorn через CLI, ответы API, локальные файлы frontend и побайтовые экспорты.
Одна сторонняя deprecation warning Starlette/httpx не влияет на результаты.

Для повторения совместного прогона после подключения отдельного checkout C:

```bash
python -m pip install '.[serve,dev]'
MONEYGRAPH_API_TESTS=1 MONEYGRAPH_DATA_DIR=./data MONEYGRAPH_SNAPSHOT_DIR=./out/runs/RUN_ID PYTHONPATH=.:../moneygraph-api python -m pytest tests ../moneygraph-api/tests/api -q
```

Заменить RUN_ID на каталог уже созданного снимка. Эта переменная включает
дополнительную файловую проверку C, которая открывает все 2 248 карточек.
Без `MONEYGRAPH_API_TESTS=1` четыре интеграционных теста API пропускаются;
после явного включения отсутствие C/зависимостей/датасета считается ошибкой.
