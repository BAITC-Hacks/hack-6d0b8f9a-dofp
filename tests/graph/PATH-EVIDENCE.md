# Полная цепочка переводов — передача A → C

Ветка: `codex/path-evidence`, база A `dfc1ed0`. Независима от `codex/daily-activity`.
Из существующего кода меняется только `moneygraph/analytics/graph.py`; остальные
изменения — новые файлы в tests/graph. Код API, UI, скоринг, зависимости и README
не изменены. Это готовый расчётный метод и локальный просмотр, **не уже встроенная
кнопка в основном приложении**.

## Зачем отдельный режим

В C `9038d9e` карточка показывает сохранённые пути от исходных клиентов. Нажатие
на ID выбирает отдельный узел. Обычный endpoint графа ограничивает окрестность
1–2 шагами и количеством узлов, поэтому не гарантирует целиком видимый путь из
четырёх переводов. Новый метод берёт один сохранённый пример из полного графа
снимка, без применения фильтров очереди, сообщества и лимита окрестности.

## Контракт

```python
from moneygraph.analytics.graph import seed_path_view

view = seed_path_view(graph, gid, paths, path_index=0, max_hops=4)
```

- graph: полный нормализованный nx.DiGraph из `build_graph`, с целыми ID и
  целочисленными sum_minor/n_tx на рёбрах. Не подграф текущего экрана.
- gid: существующий выбранный клиент; int64 или его точная десятичная строка.
- paths: сохранённые `seed_paths` A или `paths` C именно этого клиента из того же
  снимка. Методу не нужно заново считать PageRank, сообщества или BFS.
- path_index: индекс выбранного примера с нуля. Порядок примеров сохраняется.
- max_hops: максимум рёбер в пути; по условиям кейса 4.

Результат `seed-path-view.v1`:

| Поле | Содержание |
|---|---|
| state | found / no_saved_paths / paths_unavailable |
| view_mode / focus_gid | seed_path / выбранный клиент |
| path_index / available_paths | Выбранный индекс и число сохранённых примеров; это не число всех возможных путей |
| path | Все ID от исходного клиента до выбранного, по порядку |
| nodes | gid, depth, is_seed, step_index; от двух до пяти узлов для найденного пути |
| edges | Только последовательные стрелки пути: src, dst, sum_minor, n_tx, step_index, edge_id |
| total_nodes / total_edges | Размер полного выбранного пути |
| hidden_nodes / hidden_edges / truncated | 0 / 0 / false; путь не обрезается |
| warnings | Ограничения интерпретации |

ID и суммы в JSON — строки. edge_id соответствует формату Cytoscape C
`src->dst`. step_index для узлов начинается с 0, для рёбер — с 1. Это порядок
в выбранном маршруте, **не depth и не иерархия участников**.

Метод не строит индуцированный подграф: обратные стрелки и дополнительные связи
между теми же узлами не добавляются. Они доступны в обычном исследовании сети.
Все суммы на стрелках — агрегаты пары клиентов за весь период, а не оценка
суммы, прошедшей весь маршрут. Складывать их в «оборот цепочки» нельзя.

Неизвестный gid вызывает KeyError. Неверный индекс — ValueError/IndexError.
Устаревший/невалидный путь (нет узла, нет направленного ребра, неверные начало
или конец, цикл или более четырёх рёбер) — ValueError. Частичный путь не отдаётся.
Список [] означает отсутствие сохранённых примеров; None — недоступность данных
о путях. В обоих состояниях выбранный узел остаётся в nodes, edges пуст.

## Подключение C

Предлагаемый маршрут после согласования:
`GET /api/v1/runs/{run_id}/nodes/{gid}/path-view?path_index=0`.
Endpoint ещё не добавлен; C сохраняет свои проверки run_id/gid и JSON-envelope.

Для QueryService можно один раз при загрузке снимка построить граф-индекс:

```python
import networkx as nx

path_graph = nx.DiGraph(max_depth=4)  # фактическое значение из конфигурации снимка
for node in service.nodes.values():
    path_graph.add_node(int(node.gid), depth=node.depth, is_seed=node.is_seed)
for edge in service.edges:
    path_graph.add_edge(int(edge.src), int(edge.dst),
                        sum_minor=int(edge.sum_minor), n_tx=edge.n_tx)
```

Обработчик использует этот индекс и сохранённые пути:

```python
node = service.node(gid)  # существующая проверка клиента; ошибка -> 404
view = seed_path_view(path_graph, gid, node["paths"], path_index=path_index)
# Сохраняем стандартные поля карточки, цвета ролей и предупреждения C.
view["nodes"] = [dict(service.node(n["gid"]), step_index=n["step_index"])
                 for n in view["nodes"]]
return service.envelope(view)
```

Индекс должен принадлежать ровно тому же service/run_id. При загрузке нового
датасета пересоздавать индекс вместе с сервисом. Нельзя смешивать маршруты
старого снимка и граф нового. Не принимать список ID пути напрямую из браузера:
браузер выбирает индекс, сервер берёт сохранённый пример.

Изменения в UI C:

1. Рядом с каждым сохранённым примером — «Показать цепочку на графе».
2. Загрузить все узлы/стрелки через отдельный режим, независимо от фильтров очереди.
3. Рисовать порядок по step_index, например слева направо, с видимыми стрелками.
   Старый layout по node.depth может показывать другое расположение.
4. Подписать «Пример N из M · до четырёх переводов» и дать «Вернуться к сети».
5. При выходе восстановить прежние фильтры и положение выбранного клиента.
6. Отменять устаревшие запросы при смене клиента/run_id; не показывать прежнюю
   цепочку под заголовком нового клиента.
7. Различать отсутствие примеров, недоступность данных и ошибку целостности пути.

Постоянная подпись: «Структурная цепочка. Направления переводов подтверждены,
но движение одной и той же суммы и хронологическая последовательность не доказаны».
В tooltip ребра — сумма за период и число операций; без утверждения о времени
внутри дня. Для границы depth=4 сохраняется предупреждение о неполноте.

## Локальная демонстрация до подключения UI

```bash
python tests/graph/review_path_evidence.py --data ./data --out ../moneygraph-path-local
```

Без --gid выбирается первый по gid клиент с сохранённой четырёхшаговой цепочкой
и подходящий индекс. Это выбор наглядного примера, не приоритет расследования.
Если четырёхшаговых примеров нет, выбирается минимальный gid и первый пример.
Можно задать `--gid ID_КЛИЕНТА --path-index 0`.

Создаются `path-evidence.local.html` с полной цепочкой и таблицей и
`path-evidence.local.json` с точными значениями, периодом и хешами входов.
Открыть HTML браузером; сеть не используется. Отчёты с финансовыми данными не
коммитить. Для повторного запуска нужен новый --out, перезапись запрещена.

## Приёмка

- Четыре перевода показывают все пять клиентов, независимо от лимита окрестности.
- Обратная стрелка не подменяет нужное направление; посторонние связи исключены.
- Переключение между примерами меняет ровно выбранную цепочку.
- Изолят остаётся видимым без выдуманного маршрута.
- Все суммы и количества совпадают с исходными агрегированными рёбрами.
- Тесты `test_path_evidence.py` покрывают валидацию, int64/тиыны, изоляты,
  неизменность графа и все сохранённые примеры реального датасета при заданном
  MONEYGRAPH_DATA_DIR. Это не проверка браузера C и не оценка качества AML-модели.
