## Простыми словами

Участник графа считает показатели каждого клиента: от скольких людей поступили
деньги, скольким он отправил, какие суммы и связи видны в данных.

Наша часть принимает готовые показатели и отвечает на три вопроса:

1. Какую роль клиент предположительно выполняет: собирает, распределяет,
   передаёт деньги дальше, является возможным концом цепочки или координатором?
2. Кого аналитику полезнее проверить сначала?
3. На каких конкретных числах основано это предположение и чего мы не знаем?

Пример для понимания: узел получает от многих разных отправителей. При выполнении
остальных условий правило может назвать его кандидатом в сборщики. Код сохраняет
количество плательщиков, условия правила и ограничения данных. Это не доказательство
нарушения и не решение о блокировке счёта.

## Как открыть в VS Code на Linux

Выполняй команды по очереди. Этот вариант создаёт отдельную папку для нашей ветки.
Git и VS Code должны быть установлены, а GitHub-аккаунт — иметь доступ к приватному
репозиторию. Если папка `~/moneygraph-scoring` уже создана, повторное клонирование
не нужно: переходи к разделу обновления.

```bash
cd ~
git clone --branch codex/scoring-rules https://github.com/BAITC-Hacks/hack-6d0b8f9a-dofp.git moneygraph-scoring
cd moneygraph-scoring
code .
```

`code .` открывает текущую папку. Если команда code не найдена, открой VS Code
вручную и выбери File → Open Folder → moneygraph-scoring в домашней папке.
При ошибке доступа нужно авторизовать Git на своём компьютере; подключение GitHub
в чате автоматически не авторизует терминал ноутбука. Токены в чат не отправляй.

Открой `docs/scoring-progress.md`; предпросмотр Markdown — Ctrl+Shift+V.

## Как видеть новые изменения

После сообщения, что новый коммит отправлен в нашу ветку, в терминале проекта:

```bash
cd ~/moneygraph-scoring
git status --short --branch
git pull --ff-only
git log -5 --oneline
```

Проверь, что status показывает `codex/scoring-rules`. Pull получает опубликованные
коммиты; VS Code затем показывает обновлённые файлы. Это не трансляция набора текста:
неотправленные изменения из рабочей среды ассистента на ноутбуке не появляются.

Если Git сообщает о конфликте, расходящихся ветках или локальных изменениях,
остановись и передай текст сообщения. Не используй reset --hard или force push
для решения такой ситуации. `--ff-only` не создаёт неожиданный merge-коммит.

Последний коммит и затронутые им файлы:

```bash
git show --stat HEAD
```

Посмотреть ветки команды без их изменения:

```bash
git fetch origin
git branch -r
```

## Как проверить нашу часть

В терминале из корня проекта с Python 3.12:

```bash
python3 --version
python3 -B -m unittest discover -s tests/scoring -v
```

Для этих тестов не нужны pandas, графовые библиотеки, данные или API-ключи.
Успешный результат заканчивается `OK`. Это тесты скоринга, не запуск интерфейса.
