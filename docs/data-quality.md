# Данные: проверка целостности и ограничения наблюдения

Владелец: роль A («данные и граф»). Реализовано в `moneygraph/io/load.py` и `validate.py`.
Данные организаторов не входят в Git. Файлы берутся из локального каталога, переданного вызывающим кодом.

## Что реализовано

Загружаются `nodes.parquet`, `edges.parquet`, `transactions.parquet`. SHA-256 вычисляется по тем же байтам, которые читает Parquet-парсер. Возвращаются нормализованные копии таблиц и JSON-совместимый словарь качества; запись quality.json и снимка — задача роли B.

Ошибки обязательных колонок, null, типов идентификаторов, уникальности gid/рёбер, неизвестных концов связей, depth/is_seed, сумм, n_tx, дат или сверки потоков вызывают `DataValidationError`. Неверный Parquet/отсутствующий файл даёт ошибку чтения. Расчёт не должен публиковать снимок при любой из этих ошибок.

Суммы переводятся через `Decimal(str(value))` в целые тиыны (`sum_minor`), без молчаливого округления. Третья значащая цифра после запятой, неположительные и бесконечные значения запрещены. Агрегация выполняется Python-целыми; общий оборот проверяется на диапазон int64. Сверяются все пары src/dst, суммы в тиынах и n_tx. Порог применяется к отдельным транзакциям, не к агрегированному ребру.

Начало и конец периода задаются явно. Последняя наблюдаемая операция не определяет конец выгрузки. По умолчанию глубина 4, порог 500 000 тиынов (5 000 KZT). Объём 2 248 узлов не зашит в алгоритм.

Каждая транзакция получает `tx_ref`: номер строки, начиная с 0, в исходном файле. Ссылка имеет смысл только вместе с SHA-256 transactions.parquet. Совпадающие строки не удаляются: без банковского ID нельзя отличить дубль записи от повторной операции. При перестановке исходных строк tx_ref и хеш меняются, а бизнес-признаки, сообщества и маршруты остаются теми же.

## Неполнота данных

| Код в признаках | Условие и смысл |
|---|---|
| `depth_boundary` | depth=max_depth; исходящие за границей обхода могут быть неизвестны |
| `seed_inflow_incomplete` | is_seed; входящие извне выборки не наблюдаются |
| `isolated` | Нет ни одного ребра, включая self-loop |
| `out_exceeds_observed_in` | Наблюдаемый выход больше входа; не доказывает аномалию |
| `month_end_window` | Последнее поступление позднее period_end−2 дня |
| `date_only` | Порядок операций одного дня неизвестен |
| `sampling_threshold` | Переводы ниже порога не наблюдаются |
| `self_transfer` | Есть self-loop; входит в суммы, не в уникальных контрагентов |

Глобальные ограничения `intrabank_only` и `outgoing_sample` находятся в quality.warnings. `flow_ratio_eligible=False` у seed, граничных узлов и при нулевом входе. Отношение потоков всё равно доступно при положительном входе для диагностики, но его нельзя автоматически использовать в правилах transit/terminal.

Ни отсутствие исходящих, ни графовая близость, ни большое количество контрагентов не являются доказательством виновности. Оборот сети повторно учитывает деньги, проходящие несколько переводов; это не объём уникальных средств.

## Для README-питча

Подтверждённое преимущество блока: сохраняет всех участников, включая невидимых в рёбрах, проверяет деньги с точностью до тиына и передаёт ограничения наблюдения вместе с признаками. Это позволяет следующему слою объяснять гипотезы на проверяемых фактах, не выдавая обрыв выгрузки за конечную точку движения денег.

Нельзя заявлять качество обнаружения преступных групп, снижение ложных тревог или банковскую эффективность: таких измерений и размеченной истины нет.

## Дополнение после ревью тимлида

Контракт A → B и результаты устойчивости опубликованы в [методике графа](graph-methodology.md). Baseline resolution=1.0 не изменён. При resolution 0.8/1.0/1.2 получены 99/105/123 сообщества; ARI к baseline — 0.941680/1/0.883406. Это чувствительность группировки к параметру, не оценка правильности AML-гипотез.

Реальные сценарии демо выбираются локальной командой `python tests/graph/review_graph.py --data ./data --out ../moneygraph-review-local`. Идентификаторы и доказательные пути записываются в `demo-scenarios.local.json` вне checkout; в Git попадает только метод выбора, без финансовых строк и фиксированных gid.

Добавлены явные проверки возврата к seed через цикл, невозможности учитывать его как собственный источник, допуска пути ровно из четырёх рёбер и исключения пятого перехода. Лимит трёх примеров не ограничивает число учитываемых seed. Вместе с прежними проверками: 33 теста прошли на полном наборе.

Независимая приёмка CLI B `430c6e0` подтвердила сохранение всех 28 колонок features, всех исходных узлов и операций, повторов, флагов и маршрутов. Точная сверка оборотов прошла после чтения файлов. Исходники B не менялись. Паркетные списки при чтении стали numpy.ndarray — это ожидаемая особенность контейнера; для повторного скоринга B должен нормализовать их, прямой путь уже совместим.
